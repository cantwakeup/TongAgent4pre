# TongHarness Demo 讲解脚本

建议控制在 3 分钟左右。整个网页只回答一个问题：

> TongHarness 如何把主办方给定的 SimpleAgent，扩展成可执行、可恢复、可审计的长程检索研究系统？

## 录制前

1. 浏览器使用 1920×1080，缩放保持 100%。
2. 打开首页后先点击右上角“重置”。
3. 不要一开始逐项解释所有指标。
4. 轨迹顺序固定为：顺利完成 → 改写查询后完成 → 预算保护停止 → 中断后恢复。

## 00:00–00:25 开场：先交代基座和扩展边界

停留在页面顶部，不点击。

讲：

> 我们的工作叫 TongHarness。它基于主办方给定的 SimpleAgent 实现，不替换原来的 ReAct 决策循环，而是在外侧增加统一检索、预算、检查点、恢复、完整轨迹和后验审计。今天页面展示的不是虚构流程，而是冻结正式实验的真实运行记录。

## 00:25–00:50 解释 SimpleAgent 如何变成长程研究系统

指向页面中间的 `SimpleAgent → AgentHarness`。

讲：

> 左边是给定的 SimpleAgent，保留 ReAct、搜索和页面抓取；右边是我们的 AgentHarness 长程研究扩展。两边提示词、模型、工具和预算一致。Harness 只增加检查点与恢复、重试与预算、轨迹与审计，所以原始模型答案和最终答案保持一致。

这里不要讲历史版本，也不要展开实验表格，重点是“没有重写 Agent 策略”。

## 00:50–01:35 轨迹一：顺利完成

先选择“顺利完成”，点击“重放执行轨迹”，让动画自然播放。

边播放边讲：

> 这里重放的是一次正式运行。最上方给出原始 Artifact 目录，每一步还直接标出实际代码模块和函数。`run_graph_system` 创建原子运行目录，`prepare_runtime` 构建执行环境，模型决定搜索后，`limited_web_search` 和 `SearchBroker.search` 调用统一检索，再由 `limited_fetch_url` 和 `RetrievalSession.fetch` 抓取规范来源页面。

动画结束后指向右侧结果。

讲：

> 右侧同步显示模型调用、搜索抓取、Token 和耗时。下方六项运行记录对应输入任务、工具轨迹、引用来源、最终答案、评分、成本与时延，正好形成可复现实验闭环。最重要的是原始答案等于最终答案：Harness 没有为了分数改写结果。

## 01:35–02:10 轨迹二：遇到问题后继续研究

切换“改写查询后完成”，点击重放。

讲：

> 第二条不是理想路径。第一次搜索结果相关性不足，Agent 在下一轮改写查询并继续研究；重复 URL 抓取则由 `ResearchBudget.fetch_suppression` 安全阻止。已有来源、预算状态和执行轨迹都没有丢失，最后仍生成了短答案。这体现了 SimpleAgent 被扩展后可以承担多轮长程研究，而不是只能完成一次搜索。

## 02:10–02:40 轨迹三：超预算时安全停止

切换“预算保护停止”，可用“单步”快速走到最后两个事件。

讲：

> 第三条展示失败边界。任务已经进行多轮搜索和抓取，但下一次模型调用需要预留的 Token 超过剩余额度。`EvaluationMiddleware._reserve_model_call` 触发预算保护，`run_graph_system` 保存已有轨迹和 Artifact 后安全停止。它不是 Runner Error，而是带完整记录的预算终态。

## 02:40–03:10 轨迹四：中断后从检查点继续

切换“中断后恢复”，点击重放。

讲：

> 第四条来自冻结的受控故障实验。第一次执行已经抓取来源网页，随后实验模拟进程被回收。再次启动时，`_CheckpointedGraph.invoke` 检测到原目录中的 `checkpoint.sqlite`，恢复同一任务状态，且没有重复请求已经成功抓取的网页，最后继续生成答案。这里展示的是恢复能力，不是公网 benchmark 正确率。

## 03:10–03:30 收尾：回扣主办方要求

讲：

> 所以这个 Demo 展示了三件事：第一，我们确实基于给定 SimpleAgent 扩展；第二，真实测试任务的输入、工具调用、引用、答案、评分、成本和时延都能复现；第三，AgentHarness 把一次性简单 Agent 变成了能够多轮检索、受预算控制并留下完整审计记录的长程研究系统。

## 老师追问时的三句回答

### “为什么准确率没有明显提升？”

> 因为 TongHarness Standard 被设计为不修改模型策略和原始答案。现阶段数据支持的是运行可靠性优势，我们没有把它夸大成准确率优势。

### “那工作量体现在哪里？”

> 工作量集中在统一 Retrieval、安全抓取、预算遥测、原子 Artifact、Checkpoint/Resume、故障注入、统一评分和跨系统公平评测，它们共同形成了可复现的执行与评测闭环。

### “与普通 DeepAgents Demo 有什么区别？”

> DeepAgents 提供通用 Agent 能力；TongHarness 是其上的研究执行与评测层，重点解决真实长程任务的预算、恢复、轨迹、审计和公平比较。
